# Tailwind CSS Benchmark

This repository contains an Rsbuild React benchmark that compares Tailwind CSS v4 integration through `@rsbuild/plugin-tailwindcss` and `@tailwindcss/postcss`.

The app code is identical for both runs. The only difference is the Rsbuild config:

- `rsbuild.plugin.config.ts` uses `@rsbuild/plugin-tailwindcss`.
- `rsbuild.postcss.config.ts` uses `@tailwindcss/postcss` through `tools.postcss`.

Lower numbers are better.

## Result

Measured on 2026-06-04.

| Metric | `@rsbuild/plugin-tailwindcss` mean | `@tailwindcss/postcss` mean | Faster |
| --- | ---: | ---: | --- |
| Production build | 13,786 ms | 11,199 ms | `@tailwindcss/postcss` by 18.8% |
| Dev cold start | 983 ms | 1,210 ms | `@rsbuild/plugin-tailwindcss` by 18.8% |
| Dev rebuild | 575 ms | 795 ms | `@rsbuild/plugin-tailwindcss` by 27.7% |

## Interpretation

In this synthetic fixture, `@tailwindcss/postcss` was faster for the full production build, while `@rsbuild/plugin-tailwindcss` was faster for dev-server startup and Tailwind-class rebuilds.

The build metric is end-to-end wall-clock time for `rsbuild build`, not an isolated Tailwind transform benchmark. It includes TypeScript/JSX compilation, CSS extraction, Tailwind generation, CSS minimization, asset writing, and Rsbuild/Rspack process overhead.

The dev rebuild metric is closer to the Tailwind integration path because the runner rewrites an imported module that contains a large deterministic Tailwind class surface, then waits for the next dev compile to complete.

## Fixture

The fixture is generated by `scripts/generate-fixture.mjs`.

- 32 generated React screens.
- 102 generated benchmark modules instead of one large component file.
- Each screen is split into `Screen`, `MetricGrid`, and `ActivityFeed` modules.
- Shared presentational components live in `src/benchmark/generated/components`.
- 8 dense rows per screen.
- 4 metric cards per screen.
- 240 generated Tailwind theme color and shadow tokens.
- 400 rebuild class groups in `src/benchmark/rebuild-target.tsx`.
- About 88,704 generated utility tokens in the main fixture.
- About 16,800 generated utility tokens in the rebuild target.
- Generated source size: `src` is 2.5 MB, including 2.1 MB under `src/benchmark/generated`.

The generated classes include theme-backed utilities, arbitrary values, responsive variants, dark variants, data/ARIA variants, `supports-*` variants, transitions, transforms, filters, outlines, rings, gradients, shadows, and layout utilities.

## Method

Run:

```bash
pnpm install
pnpm generate
pnpm benchmark
```

The benchmark script performs:

1. Three production builds per integration, deleting that integration's `dist` directory before each measured build.
2. Three dev-server cold starts per integration, measuring from process spawn to the first successful `ready built in ...` output.
3. Five rebuilds inside each dev-server run, rewriting `src/benchmark/rebuild-target.tsx` with a new deterministic class surface and measuring until the next successful compile.

Manual commands:

```bash
pnpm build:plugin
pnpm build:postcss
pnpm dev:plugin
pnpm dev:postcss
```
